## 当前任务理解

从空目录建立中文进销存应用，在本机 Docker Desktop 上启动并提供浏览器入口。商品和仓库提供维护页面。入库单可新增、修改和删除，支持数量、单价、金额任填两项或输入一致的三项。出库单提供库存成本预览和新增。库存按商品、仓库查询，商品和仓库有任一业务引用时禁止删除。

实施选择为整数数量、人民币金额保留两位小数、库存单价保留六位小数、四舍五入。单价或金额为零时需明确填写数量。出库按库存金额与数量的精确比例核算金额，出清时结清余额。改删入库按单据原创建时间重放受影响的组合，其中更换商品或仓库涉及原组合和新组合。历史任一时点库存不足则回滚整个操作。应用初始为空，默认仅对本机开放。

## 实施方案

1. 固定 API 和精度规则，后端、前端、部署分别实施。以实际 MySQL 验证五张业务表与事务回放。
2. 后端使用 Spring Boot 3、Java 21、MyBatis 和 MySQL 8.4。每次库存写入在一个事务内完成。数据库对相关商品和仓库加锁，保证并发出库和目录删除时检查与写入一致。使用外键、唯一键与定点数类型约束业务记录。
3. Vue 3 页面提供库存总览、入库单、出库单、商品、仓库。以库存表和就地表单组织操作，保留手机布局和交互反馈。
4. Docker Compose 启动 MySQL、Spring Boot 和 Nginx 前端。Nginx 代理同源 API。真实验收覆盖管理、金额计算、历史重算、跨仓及商品变更、拒绝负库存、并发和重启持久性。

### 接口约定

同源 `/api`，请求和响应使用 JSON。GET 列表返回数组，POST/PUT 返回已保存记录，DELETE 成功为 204，业务错误为 `{"message":"中文说明"}`。金额和单价在响应中采用十进制字符串以保留精度，请求也可用字符串。编号和数量使用 JSON 数字。成功创建返回 201。主数据未找到返回 404，输入错误返回 400，引用冲突或库存不足返回 409。

| 路径 | 方法 | 数据 |
|---|---|---|
| `/api/commodities` | GET、POST | `id, name, spec`，新增只提交 `name, spec` |
| `/api/commodities/{id}` | PUT、DELETE | 修改提交 `name, spec` |
| `/api/warehouses` | GET、POST | `id, name, address`，新增只提交 `name, address` |
| `/api/warehouses/{id}` | PUT、DELETE | 修改提交 `name, address` |
| `/api/inbounds` | GET、POST | 提交 `commodityId, warehouseId, quantity, unitPrice, amount`，三项数字至少两项；响应含全部单据字段 |
| `/api/inbounds/{id}` | PUT、DELETE | 修改请求同新增 |
| `/api/outbounds` | GET、POST | 新增提交 `commodityId, warehouseId, quantity`；响应含全部单据字段 |
| `/api/outbounds/quote?commodityId=&warehouseId=&quantity=` | GET | 数量可省略。返回 `availableQuantity, unitPrice, amount`，未指定数量时金额为 null，超库存时返回 409 |
| `/api/stocks` | GET | `commodityId, commodityName, warehouseId, warehouseName, quantity, unitPrice, amount` |

单据响应字段为 `id, commodityId, commodityName, warehouseId, warehouseName, quantity, unitPrice, amount, createdAt, previousQuantity, previousUnitPrice, previousAmount`。创建时间以 ISO 8601 UTC 返回。库存列表显示有结存的组合。商品规格及仓库地址可空，名称必填。
